# Mapper & DTO Package Convention — Docs + Code Migration

> Implementer note: this plan is self-contained. Every file to touch is listed with its old → new path and its known
> referencing files. All paths are relative to the repo root unless a Java package is given. Backend base package:
> `at.fraihs.cookoff`, source root `backend/src/main/java/at/fraihs/cookoff` (tests mirror it under
> `backend/src/test/java/...`).

## Context

Mappers and data types are placed inconsistently across the backend:

- `cookoff/infrastructure/persistence/mapper/` already holds its 13 mappers in a dedicated package (the target state),
  but `auth/infrastructure/persistence/AccountMapper` sits next to the repository impl.
- Application-layer mappers live inside `service` packages next to the use cases that call them:
  `auth.application.service.AccountModelMapper`, `shared.application.service.ConfigModelMapper`,
  `cookoff.application.service.ChallengeMapping`.
- Data types sit in packages meant for something else: `AccessLink` / `RegistrationInvite` / `StoredImage` are records in
  `application/port` (a package for interfaces), `ChallengeResult` is a record in `domain/service`, and the API envelope
  records sit in `shared/web` next to `GlobalExceptionHandler`.
- Both `auth/application/dto` and `cookoff/application/dto` exist but are **empty**.

The docs codify the *old* placement — `docs/backend/03-code-style.md` explicitly says "mappers stay next to the entity
they convert", and `docs/backend/01-architecture.md`'s package tree is a generic `controller/service/repository/model`
layout that does not exist anywhere in this codebase — so following the docs today reproduces the inconsistency.

Goal: one rule — **every layer puts its mappers in `mapper/` and its data types in `dto/` (application), `model/`
(domain), or `entity/` (JPA)** — documented, applied to the code, and enforced by ArchUnit so it cannot drift again.

## Target Convention

```
<module>/
├── domain/
│   ├── model/                     aggregates, VOs, enums, domain records (incl. ChallengeResult)
│   ├── service/                   domain services only (ResultCalculator)
│   └── event/
├── application/
│   ├── dto/                       commands, query results, port payloads (AccessLink, RegistrationInvite, StoredImage)
│   ├── mapper/                    domain → generated-OpenAPI-model mappers
│   ├── port/                      interfaces only
│   ├── service/                   use cases only
│   ├── event/
│   └── exception/
├── infrastructure/<adapter>/      adapters: persistence, image, accesslink, registrationinvite
│   ├── entity/                    *JpaEntity, @Embeddable
│   ├── mapper/                    domain ↔ entity mappers
│   └── <X>RepositoryImpl.java, <X>JpaRepository.java
└── interfaces/rest/               controllers (request/response DTOs are generated → shared.web.openapi.model)
```

Explicitly **not** moving:

- `auth/AccountLookup.java`, `auth/AccountSummary.java`, `auth/RegistrationInvites.java`, `auth/RegistrationResult.java` —
  module-root types are the Spring Modulith named interface of the auth module; moving them would need new
  `@NamedInterface` declarations for no benefit.
- `cookoff/application/service/RivalryHeadline.java` — a display-text helper, neither mapper nor model.
- `SubmitScoreService.Result` (nested record) — documented exemption, see Step 1.
- Everything under `at.fraihs.cookoff.shared.web.openapi..` — generated by the openapi-generator at build time into
  `backend/build/generated/openapi`; never edit, and exclude from the new ArchUnit rules (see Step 3).

## Step 3 — ArchUnit Enforcement

Add a new test class `backend/src/test/java/at/fraihs/cookoff/PackageConventionArchitectureTests.java` (keeping
`JMoleculesArchitectureTests` focused on the jMolecules/layering rules), following that file's existing style:
`@AnalyzeClasses(packages = "at.fraihs.cookoff", importOptions = ...)` with `static final ArchRule` fields annotated
`@ArchTest`.

Rules to encode:

1. Classes with a simple name ending in `Mapper` must reside in a package matching `..mapper..`.
2. Classes annotated `@Mapper` (MapStruct) must reside in `..mapper..`.
3. Classes annotated `@Entity` or `@Embeddable` must reside in `..entity..`.
4. Top-level records must not reside in `..application.service..`, `..application.port..`, or `..domain.service..` —
   they belong in `..dto..` / `..model..`.

**Two details that will otherwise make the rules fail or under-enforce:**

- `@AnalyzeClasses(packages = "at.fraihs.cookoff")` also imports the openapi-generated sources
  (`at.fraihs.cookoff.shared.web.openapi..`, wired into the main sourceSet by `backend/build.gradle.kts`). Every rule
  must exclude that package — cleanest is a custom `ImportOption` rejecting locations containing `/openapi/`, combined
  with the existing `ImportOption.DoNotIncludeTests.class`; otherwise the generated `*RestDto` models blow up rule 4.
- Rule 4 must be limited to **top-level** classes (in ArchUnit: `.that(are(topLevelClasses()))` /
  `JavaClass::isTopLevelClass`) so the documented `SubmitScoreService.Result` exemption survives.

Each rule should carry an `.because(...)` message pointing at `docs/backend/03-code-style.md` so a future failure
explains itself.

   packages are removed; this also re-runs `openApiGenerate` and the full compile.
2. `cd backend && ./gradlew test`, paying attention to:
   - `PackageConventionArchitectureTests` (new rules pass) and `JMoleculesArchitectureTests` (layering still holds — the
     `..interfaces..`/`..application..`/`..domain..`/`..infrastructure..` matchers still match the new subpackages),
   - `ModularityTests` (`modules.verify()` — catches any named-interface or cross-module access broken by the moves),
   - the `@DataJpaTest` persistence tests (entities resolved from their new `entity` packages),
   - `CookoffApplicationTests` (context loads → every mapper bean still wired, including MapStruct-generated ones).

   Per `CLAUDE.md`, prefer running tests through the IntelliJ MCP server where available; use Bash only for shell commands.
3. Negative check: temporarily drop a `public record Foo(int a) {}` into `cookoff/application/service`, confirm rule 4
   fails the build, then revert.
4. `git diff --stat` sanity check — the diff should be `package`/`import` lines only, except the
   `ChallengeMapping` → `ChallengeModelMapper` rename and its `public` visibility bump.
5. Re-read the three backend docs against `find backend/src/main/java -type d` and confirm the documented tree and the
   actual tree match exactly.
