# Internationalization (English + German)

The UI is available in English (`en`, the fallback) and German (`de`). The language is chosen
automatically from the browser/device language — there is no switcher. It uses
[Transloco](https://jsverse.gitbook.io/transloco) at runtime: one build, one URL, translation
files loaded from `public/i18n/<lang>.json`.

## How the language is chosen

`core/i18n/locale.ts` → `detectLocale()` is the **single source of truth**. It takes the first entry
of `navigator.languages` whose primary subtag is supported (`de-AT`, `de-CH` → `de`), else `en`.
`provideI18n()` (`core/i18n/i18n.ts`, wired in `app.config.ts`) uses that one result for:

- Transloco's active language, loaded **before** the app renders (no raw keys flash)
- Angular's `LOCALE_ID`, so `DatePipe` etc. format for German (`registerLocaleData(de)`)
- `<html lang>`
- Material's paginator labels (`TranslatedPaginatorIntl`)
- route titles (`TranslatedTitleStrategy`; route `title` values are translation keys)

The language cannot change while the app runs, so translating in a field initializer or in a
`form()` schema is safe.

## Adding or changing text

1. Add the key to **both** `public/i18n/en.json` and `public/i18n/de.json`. The files are nested
   objects, keyed by feature (`challengeDetail.closeDialog.title`).
2. Use it:
   - Template: `{{ 'feature.key' | transloco }}`, with parameters `| transloco: { name: value }`.
     For attributes: `[attr.aria-label]="'feature.key' | transloco"` (also `placeholder`, `alt`,
     `matTooltip`). Import `TranslocoPipe`.
   - TypeScript (snackbars, confirm-dialog data, Signal Forms `message:`, computed labels):
     `inject(TranslocoService).translate('feature.key', { name })`.
3. `translations.spec.ts` fails if the files differ in keys, `{{parameters}}` or blank messages.

Rules:

- **Never build a sentence by concatenation** (`'Open ' + a + ' vs ' + b`). Word order differs
  between languages; use one message with `{{parameters}}`.
- **No markup inside messages.** If part of a sentence is emphasized, split it around the element
  (see `participantCard.ownColorBefore` / `ownColorAfter`).
- **Plurals:** two keys and pick one in code (`starRating.one` / `starRating.other`).
- **Don't show server prose.** The backend's English `message`, `headline`, `outcomeLabel` and
  `PublicRegistrationResult.message` are not displayed. See below.
- Icon names, the brand "CookOff" and example placeholders (`anna@example.com`) are not translated.

## Backend text

- **Errors:** `errorInterceptor` turns the stable `error.code` into `ApiError.message` via
  `errors.<CODE>`. Components keep using `error.message`. An unknown code gets
  `errors.UNKNOWN_ERROR`. When the backend gains a new code, add it to `API_ERROR_CODES` and both
  files.
- **Rivalry text** (`headline`, `outcomeLabel`): built in the UI by `RivalryText` from the counts
  and names the response already carries.
- **Category names** (`category.<CODE>`), **status** (`status.<CODE>`), **roles** (`roles.<CODE>`):
  keyed by the enum values the API sends.
- **Plate colors** come from `/config` with English names; `plateColorName` (pipe) and
  `translatePlateColor()` translate known ones via `plateColor.<name>` and keep the server's name
  for a color that has no translation yet.

## Account language (for emails)

Emails are sent by an organizer/admin to someone else, so the *recipient's* language is stored on
their account (`accounts.locale`, `en` | `de`, default `en`):

- `Auth` calls `PUT /api/v1/me/locale` after every login / access-link login (best effort).
- Public registration and the admin create/edit dialog send `locale`.

## Testing

Add `provideTestI18n()` (`src/app/testing/i18n.ts`) to a TestBed's `providers`. It loads the real
`en.json`/`de.json` synchronously; `provideTestI18n('de')` renders in German. Assert on the English
copy as usual.
